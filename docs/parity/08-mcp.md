# 08 MCP server

Present only when `mcp.enabled` is true (CFG-13). Built behind the cargo feature `mcp`. Each Route can be exposed as an MCP tool that calls the Upstream Service.

Rows MCP-15 and MCP-16 keep reference quirks on purpose (approved under Q17 row 11).

## Endpoint

| ID | Behaviour | Reference | Test | Status |
|---|---|---|---|---|
| MCP-01 | The endpoint is `POST /mcp`. Express matches the path case-insensitively, with or without one trailing slash and with any query string (`/MCP`, `/mcp/`, `/mcp?x=1`). Other methods on `/mcp`, and other paths such as `/mcp/x` or `//mcp`, go to the proxy (with no service claiming them: 503 `{"message":"Service Unavailable","statusCode":503}`). | `mcp/controllers/mcp.controller.ts:9-12` | C | todo |
| MCP-02 | Streamable HTTP transport in stateless mode (TypeScript SDK 1.32): every request is handled on its own, with no session id issued and any `mcp-session-id` ignored. Compared at the JSON-RPC message level. Requests are answered as `text/event-stream` (`event: message` + `data:` per message); notifications and client responses get 202 with no body; batches are accepted (one event per response, 202 when they hold no request, also for `[]`). `initialize` echoes a supported protocol version (2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05, 2024-10-07) and otherwise answers 2025-11-25. Unknown methods, and methods of capabilities the server lacks, give `-32601` `Method not found`. Transport errors are JSON-RPC error bodies with `id: null` and `content-type: application/json`: 406 without both media types in `Accept`, 415 for another content type, 400 `-32700` `Parse error: Invalid JSON` or `Parse error: Invalid JSON-RPC message`, 400 for an unsupported `mcp-protocol-version`. Invalid `tools/call` parameters give `-32603` with the SDK's validation text. | `mcp/services/mcp-server.service.ts:34-42` | C | todo |
| MCP-03 | Server info defaults to name `nestjs-api-gateway` and version `1.0.0`, each replaceable by options. The server advertises the capability `tools.listChanged`. | `mcp/services/mcp-server.service.ts:57-63` | C | todo |
| MCP-04 | MCP authentication handlers run in ascending priority before any protocol handling (before `Accept`, content type and body are checked). The first that does not authenticate ends the request with 401 and body `{"error":"Unauthorized"}` (`application/json; charset=utf-8`), unless the handler already wrote its own response. A handler that throws gives Nest's 500 `{"statusCode":500,"message":"Internal server error"}`. | `mcp/services/mcp-server.service.ts:44-54` | C | todo |
