## Example binary `rust-gateway-server`

An example only (Q11), mirroring `src/` of the reference. It is also the target of the Conformance Tests and benchmarks.

| ID | Behaviour | Reference | Test | Status |
|---|---|---|---|---|
| EX-01 | Reads the same environment variables as the reference sample: `APP_PORT` (default 3000), `REDIS_HOST` (default `localhost`), `REDIS_PORT` (default 6379), `REDIS_DB` (default 0), `REDIS_USERNAME`, `REDIS_PASSWORD`, `REDIS_TLS`, `REDIS_TLS_CA_FILE`, `REDIS_TLS_CERT_FILE`, `REDIS_TLS_KEY_FILE`, `REDIS_TLS_SERVERNAME`, `REDIS_TLS_REJECT_UNAUTHORIZED`. | `src/config/env.config.ts:12-51` | R (`config::tests::ex_01_ex_04_sample_defaults`, `config::tests::ex_01_ex_02_sample_environment`) | done |
| EX-02 | Upstream Services are defined in code in the reference sample (`user-service` at `http://localhost:4020` with Direct Prefixes `oauth` and `oidc`). The example additionally accepts them from an environment variable (`API_SERVICES`, a JSON list) so tests and benchmarks can point it at mock upstreams. With `GATEWAY_CONFIG` set, it reads the conformance configuration file instead. | `src/config/env.config.ts:31-38` | R (`config::tests::ex_01_ex_02_sample_environment`) | done |
| EX-03 | Registers one handler of each kind, equivalent to the reference sample: a proxy middleware and a WebSocket middleware that set the header `auth-user-id`, a static predicate for URLs containing `/images/` or `/statics/`, and an MCP authentication handler that accepts everything. | `src/middleware/*.ts` | R (`sample::tests::ex_03_sample_handlers`) | done |
| EX-04 | Uses the reference sample's settings: exclude headers `auth-user-id` and `permission-in-any-guard`; bearer key `auth-user-id`; API key `x-api-key`; all four limits at 60 per 60 s; documents and MCP enabled; trusted proxies `loopback`, `linklocal`, `uniquelocal`; 100 connections per Upstream Service. | `src/app.module.ts:16-55`; `src/main.ts:23` | R (`config::tests::ex_01_ex_04_sample_defaults`) | done |
| EX-05 | A second, representative middleware set for benchmarks, selected with `GATEWAY_MIDDLEWARE=bench` next to `GATEWAY_CONFIG` (`src/bench.rs`): verify an HS256 JWT bearer token signed with `BENCH_JWT_SECRET` (`exp` and `nbf` checked when present, no clock tolerance, as `jsonwebtoken`'s `verify` in Node), set `auth-user-id` to its `sub`, answer 401 `{"message":"Unauthorized","statusCode":401}` for a bad token, or for no token on a Route that requires bearer authentication; resolve the Identity as the user id (authenticated) or the client address. The same logic is in the reference app used in benchmarks (`benches/reference/src/middleware.ts`), and the load test's pre-check requires both gateways to answer each scenario with the same status and body. The user confirmed on 2026-11-18 that it is representative of their production middleware. | none (benchmark only) | R (`bench::tests::ex_05_valid_token_sets_the_user`, `bench::tests::ex_05_bad_tokens_are_rejected`, `bench::tests::ex_05_missing_token_depends_on_the_route`, `bench::tests::ex_05_identity_is_user_or_address`) | done |
| EX-06 | Serves application routes of its own next to the gateway, like the reference sample's `/` and `/oauth/metadata`, to demonstrate CFG-18. | `src/app.controller.ts:12-34` | R (`sample::tests::ex_06_sample_routes`, `gateway_pipeline::cfg_18_application_routes_take_precedence`) | done |
