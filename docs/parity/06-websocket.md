# 06 WebSocket proxying

Upgrade requests take a separate, shorter path than HTTP requests. Several behaviours here differ from HTTP forwarding on purpose, because Upstream Services already depend on them.

An upgrade never goes through the Route lookup or the proxy middleware, so in the pinned reference (12.4.2) `Connection: Upgrade` + `Upgrade: websocket` let any client reach any upstream path unauthenticated and unthrottled, and read the upstream's answer when it did not upgrade. **Deviation D15** closes that, as the Reference Gateway itself does from 12.5.0: the order is WS-02, WS-06, WS-17, WS-03, WS-18 (Global IP), WS-04 (and WS-18 Anonymous IP on a rejection), then forwarding.
