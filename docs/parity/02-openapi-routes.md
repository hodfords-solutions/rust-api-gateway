## Port notes

Decisions the rows leave open, each checked against the reference and tested. The port is `api-gateway`'s `route` and `openapi` modules.

- **Rejected patterns.** A match pattern `path-to-regexp` rejects, whether it comes from `x-router-path` or from the OpenAPI path (`/items({id})` becomes `/items(:id)`), fails the whole document, like every other error while building the Route table: a service that never loaded answers 503, one that loaded keeps its previous Routes (OAS-03). The same holds for an operation that is `null`, an `x-router-path` that is neither a string nor a list of strings, and a `security` value that is not a list. `openapi::oas_10_rejected_pattern_fails_the_document` shows the reference doing this.
- **Original document.** As in the reference, a changed document replaces the stored original JSON (`originDocs`) even when its Routes cannot be built, and that document is not retried until it changes again. A body that is not JSON is stored as a string.
- **`x-router-path` lists.** The reference passes the value to `path-to-regexp` unchanged, so a list of patterns matches any of them; `router_path` is then the list joined with commas.
- **`x-rate-limits` numbers.** `limit` is rounded up and negative values become 0, which compares the same against the integer counters; `ttl` is kept as given; a truthy `status` that can never equal a response status (`200.5`, `-1`, `"201"`, `true`) becomes `u16::MAX`, so the Route still counts on the status path and never increments, as the reference does. Entries that are not objects are skipped, and a missing or non-numeric `limit` or `ttl` reads as 0 or NaN; the reference answers 500 or 429 for those depending on the path, which the port does not reproduce.
- **Operations that are not objects.** A string, number, boolean or list builds a Route with no fields, whose `extra` holds the value's JavaScript index keys, as the reference does.
- **Lookup failures.** A request URL `new URL()` rejects, and a matched parameter that is not valid percent-encoded UTF-8 on its own, make the lookup fail; the reference answers 500 (`openapi::oas_19_undecodable_parameter_fails_the_lookup`).
- **URL path.** `getPathFromUrl` is reproduced with the `url` crate plus Node's encoding of `^`, which the crate does not apply yet (`route::uri::tests::oas_18_ascii_characters_are_encoded_like_node`).
- **Identifier characters.** Parameter names follow Node's Unicode 17 `ID_Start` and `ID_Continue` tables, generated with the golden vectors.
